## 1. 拍摄对象边界

本站图片**只允许出现**：金属件、硅胶件、外设、工具、桌面、示意图表。

理由不是审美洁癖，是三条很硬的实际约束：

1. 平台侧：涉及人体的肛肠相关特写在国内主流平台几乎必然触发审核；
2. 传播侧：读者要判断的是"这件东西做得怎么样"，给器械质感比给身体局部信息量更大；
3. 我这一侧：器材可以复拍、可以量、可以对照规格表，身体不行。

:::note 如果确实需要表达"贴合度"
用**投影/轮廓**代替实拍：白纸描边扫描、或在纯黑背景上拍剪影。这类图反而比皮肤特写更能说明法兰边缘的形状。
:::

## 2. 四个标准机位（每次上新器材都按这套拍，图与图之间才可比）

| 编号 | 机位 | 参数 | 用途 |
|---|---|---|---|
| S1 | 正俯拍平置，接口朝上 | 50–90 mm，f/8，1/125 s，ISO 100，自然窗光 + 白色反光板 | 展示外形对称性与法兰外径 |
| S2 | 微距正打螺纹口 | 90–105 mm 微距，f/11，焦点在牙顶，旁边放 1 元硬币（25 mm）做比例尺 | 牙型、加工质量、防松点 |
| S3 | 45° 侧逆光 | 单灯 / 窗光在后方 30°，正面黑卡收边 | 边缘倒圆与抛光过渡（靠高光连续性判断） |
| S4 | 装配序列三连拍 | 同机位固定，只换手部与配件状态 | 说明"手旋到底 → 补 1/8 圈 → 拉拽自检" |

统一要求：

- 背景：哑光深灰或纯白，**不要木纹/布纹**（会污染尺寸判读）
- 每张图带**比例参照物**（硬币或钢尺），没有参照物的器材图等于没拍
- 白平衡用灰卡，别靠自动；金属色偏了整组图都废
- 不做磨皮、不做质感增强，允许的处理只有裁切与亮度曲线

## 3. 出图规格（构建器按这个吃）

```
路径      ui/images/<slot-key>.{jpg,png}
尺寸      1600 x 1200（4:3）为首选；hero 位 1600 x 1000
格式      PNG（截图/示意图） / JPG q82（照片）
体积      单张 < 400 KB，整站图片 < 6 MB   # Pages 产物是纯静态，别把仓库塞爆
命名      小写连字符，与 src/slots.json 的 key 一致
```

### 当前还缺的图位

`bristol`（布里斯托 5 型示意图）仍在 `pending`，正文里会显示占位块而不是破图——这是有意的：**占位块 = 待补，破图 = 出事了**，两种状态必须长得不一样。补法见下。

## 4. 图位工作流（本仓库的实现方式）

正文里不写死图片路径，只写图位：

```markdown
{{slot:hero-base}}
```

然后在 `src/slots.json` 登记：

```json
"hero-base": {
  "src": "assets/images/hero-base.png",
  "alt": "316L 底座平置特写，中央接口朝上",
  "caption": "图 01 / 底座平置，M8x1.25 内螺纹座朝上。",
  "status": "ready"
}
```

`status` 不是 `ready` 时，构建器输出一个**占位块**而不是破图。这样"图还没拍完"和"图丢了"在两代人眼里是两种状态，不会互相误判。

```bash
cp 你的图.jpg ui/images/hero-base.jpg      # 改 status 为 ready
node build/build.js
```

### 可选：GitHub 原始链接当图床

如果不想把大图塞进仓库，可以开一个纯图片仓库，正文里直接用：

```
https://raw.githubusercontent.com/<user>/<img-repo>/<branch>/<path>.png
```

注意：`raw.githubusercontent.com` 在部分地区不稳；而且**外链图床不受版本控制**，图片改名即断链。所以默认策略还是图片进本仓库，外链只当临时方案。

## 5. 分发与平台适配

| 渠道 | 可行性 | 做法 |
|---|---|---|
| 自有静态站（Pages / Vercel） | 高 | 全文 + 图，唯一不受算法摆布的存档位置 |
| X 长文 / Thread | 中高 | 器材图 + 力学小结论，链回本站 |
| 垂直亚文化论坛 | 中 | 按板块规则，多数能接受技术向长文 |
| 小红书 / 知乎 / 公众号 | 低 | 只发"道具制作 / 材料 / 3D 打印"向切片，不带生理章节；被删概率仍然高 |

写作的三条底线：**拍器材不拍身体、讲工程不讲体验、把"装饰用途"写在第一段**。这既是合规策略，也是这套内容真正的价值所在。
